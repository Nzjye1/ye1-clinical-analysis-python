# Ye1 临床分析

从医生想回答的问题和已有数据出发，优先选一条合适的分析主线，直接完成当前能做的工作；仅追问会改变分析决定的一两个关键问题，不让医生填写 JSON 或选择编程语言。针对已有研究方案、表格、结果或修回意见分别从当前环节进入；从他处转入时保留已知信息，不假设其他 Skill 已安装或自动联通。

## 本地数据与隐私

1. 确认数据位置、使用权限和可在患者数据所在电脑运行的工具。原始或逐行患者记录、身份对照表、逐人模型预测和私有日志不得进入聊天、模型工具输出或外部服务；不要用表格预览、`head` 或打印数据行。宿主的实际权限和数据流不能满足此要求时停止，说明限制。
2. 按[本地处理](references/execution.md)在本机生成新的工作副本：只删除表头明确表示姓名、手机号和身份证号的列，保留其他研究字段和所有日期时间；不覆盖原件。需要研究 ID 时保留已有 ID；只有已明确每行是不同患者才可用临时行号，不能猜测跨表身份。直接标识以外的信息仍可能敏感，不能宣称完全匿名。复杂 Excel 如果涉及公式、合并单元格或图表等且需删除标识列，工具会停止；请在本机核对形成普通工作表。
3. 只向模型返回工具状态、路径、允许查看的字段说明和汇总；`private/` 中的配对 ID、模型等不读入对话或外发。具体导入、计算与输出由本地工具执行。严禁把患者数据上传网络或自动发给第三方。

## 分析主线

- 先判断研究对象、独立单位、结局与分组；提供已知变量的含义、编码、单位和缺失规则。未知的事件码、参照组、独立性、随访起点或实际变量含义不得猜测。
- 常规描述、组间比较和成对前后比较优先使用 `baseline` / `paired`，相关性、正态性、重复测量及诊断指标按需使用 `correlation`、`normality`、`repeated`、`diagnostic` 与 `diagnostic_roc`。按问题和实际数据指定适用检验；不因单个正态性检验 P 值机械切换方法，不把基线 P 值当作因果证据或自动筛选变量的依据。
- 线性 / Logistic 回归使用 `association`，明确暴露、结局、协变量、分类参照组和完整病例处理；未满足独立性、编码、模型估计或数据量条件时按阻断结果反馈，不替用户删行、换模型或追求显著性。
- 右删失 KM / Cox 使用 `survival`，明确时间起点、单位、事件及删失定义；有明确竞争事件且问题适用时，可使用限定的 Aalen–Johansen 累积发生率或原因别 Cox，不把它说成 Fine–Gray 模型。重复事件、左截断、时变协变量、复杂抽样与聚类资料不按普通 KM/Cox 强行处理；若未做正式 PH 检查，不声称比例风险假设已成立。
- 经研究方案明确时，可用 `matching` 做固定 1:1 倾向评分匹配及配对结局，报告缺失和匹配前后平衡；未测混杂和因果识别仍需复核。可按需使用 `prediction`、`prediction_forest`、`prediction_hgb` 做限定二分类预测，`continuous_prediction` 做限定连续结局预测；预先确定变量时间、结局、分割、缺失处理和固定参数，训练内处理、独立留出评估，不能将内部验证或 DCA 当临床应用证明。
- 限定场景下，`longitudinal` 支持连续结局的随机截距纵向模型，`gee` 支持连续或二分类结局的重复测量广义估计方程，`mediation` 支持二分类暴露与连续中介、结局的线性分解，`clustering` 支持探索性 KMeans/Gaussian mixture；这些并不等于正式潜类别轨迹或已证实的因果机制。`sample_size` 根据明确假设计算基础精度或双组样本量。具体约束见[方法边界](references/methods.md)和[扩充方法格式](references/expanded.md)。
- 方法不足以支持任务时明确说明，先交付已完成部分。确有研究需要时，Agent 可在宿主允许的本机环境中参考可靠方法文献另写 Python 分析，并对代码、假设和结果作独立核对；确需 R 且宿主实际支持时，也可按用户要求在本机写 R，包本身不含 R 文件。新增脚本是该次任务的工作，不冒充本 Skill 内置或已验证能力；无法核对时如实停下或标明待审核。不承诺所有原产品方法、任意模型、投稿、临床决策或发表。解释时给出分母、事件数、估计量、置信区间、适用的 P 值、限制和下一步；不凭文本捏造计算。

## 执行

先读[本地执行与任务格式](references/execution.md)，由 Agent 自行[准备并复用所需环境](references/environment.md)，首次准备或环境变化时做必要自检；已就绪的环境直接推进分析。医生只需提出研究需求，在宿主要求时确认，不必自行下载软件、选择依赖或输入命令。使用 `scripts/clinical.py` 的 `doctor`、`prepare`、`inspect`、`run`；样本量规划使用 `plan`，由 Agent 在本地准备任务文件。每次分析使用新的输出目录，检查实际结果和状态后再汇报；保留可复现的代码、任务参数和实际依赖版本。
